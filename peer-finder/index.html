ITM.690 인공지능 경영과 법 · 과제 (ii) Vercel로 배포한 웹앱

코스닥 비교기업 검색

사업 설명이나 상장사 하나를 넣으면 사업이 비슷한 코스닥 상장사와 각 회사의 상장 당시 가치 평가·최근 실적을 보여 주는 웹앱. 공시만 근거로 답하는 챗봇 포함.

개요

VC 심사역 업무 중 상장 비교기업(피어)을 찾고 상장 당시 가치 평가를 모으는 과업을 선정. 투자설명서를 한 곳씩 열어 비교기업과 배수를 옮겨 적던 일을 검색 1회와 표 1개로 대체함.

대상 과업
퀵 스크리닝(볼지 말지 정할 때 비슷한 상장사 확인), 피어그룹 선별, 피어 배수로 기업가치 가늠
형태
Vercel에 배포한 웹앱(Flask), 공개 URL 1개
데이터
코스닥 2024.01~2026.10 신규상장 169곳·스팩합병 37곳 중 사업 설명이 있는 204곳. 금융감독원 OpenDART 공시
기능
사업 설명으로 찾기, 상장사로 찾기, 피어 표(중앙값·평균·CSV), 공시 근거 챗봇
비용
상장사로 찾기 0원, 사업 설명 검색 1회 0.01원 미만, 질문 1회 약 0.4~1.3원, 색인 1회 약 5원
접근
허용 명단 이메일(본인, 교수님·조교)만 6자리 인증코드로 로그인

스킬이 아니라 웹앱으로 만든 이유

  • 동료 심사역이 링크로 함께 쓰는 도구임. 과제 (i) 스킬은 본인 혼자 반복하는 보고서 작성 절차라 형태가 다름.
  • 입력(사업 설명) → 결과(비슷한 상장사 목록)가 정해진 검색 과업이라 화면 하나로 충분함.
  • 데이터와 API 키를 서버에 두고, 로그인·실행 기록·비용 한도로 통제해야 함.

용도

쓰는 경우

  • 처음 보는 스타트업과 사업이 비슷한 상장사가 있는지, 그 회사가 어떤 평가 모형·배수로 상장했는지 빠르게 확인
  • 피어 후보를 고르고 상장 당시 배수·공모 시총·최근 실적을 표로 비교
  • 주관사가 상장 때 고른 비교기업을 따라가며 피어 범위 넓히기

쓰지 않는 경우

  • 투자 판정. 매수·매도 의견이나 고평가·저평가 판단을 하지 않음. 챗봇도 이런 질문은 거절함.
  • 현재 시세 비교. 시세 데이터는 이용 조건상 싣지 않음(법적 검토 2번).
  • 검토 중인 딜 정보 입력. 회사명·비공개 수치·사람 이름은 넣지 않고 사업을 일반적으로 설명함(법적 검토 5번).

작동 방식

7강 판결문 검색엔진·RAG 챗봇과 같은 구조. 판결문 347건 대신 상장사 공시 204곳을 씀.

  1. 회사 목록사람KIND 신규상장·합병상장 목록을 엑셀로 내려받음. KIND가 스크립트 요청을 막아 우회하지 않고 직접 받음.
  2. 공시 수집스크립트OpenDART API로 투자설명서·사업보고서 원본을 받아 사업의 개요·주요 제품·‘인수인의 의견’ 장만 저장하고 원본은 지움. 임원·주주 장은 읽지 않음.
  3. 규칙 추출스크립트공모가 산정 요약표에서 평가 모형·적용 배수·할인율·확정 공모가를, 선정 문장에서 주관사 비교기업을 뽑음. 재무는 OpenDART 정형 API. AI를 쓰지 않음.
  4. 임베딩AI사업 개요와 제품 표를 벡터로 바꿈(qwen3-embedding-8b, 7강과 같은 모델).
  5. 검색스크립트코사인 유사도 상위 10곳. 상장사로 찾기는 저장된 벡터를 써서 외부 호출 0회.
  6. 챗봇AI질문과 가까운 8곳의 공시만 넣어 답하게 함. 인용 번호는 서버가 검증하고, 근거가 없으면 정해진 문구로 거절함.
  7. 판단심사역피어 확정과 배수 해석은 사람이 함.

수집: 이 데이터를 가져와도 되는가

1. 공시 수집 방식

조건부
쟁점
공시를 200곳 넘게 모아 가공해도 되는지, 어떤 방식으로 모을지가 문제됨.
검토
화면 크롤링은 접근 통제 우회(정보통신망법 제48조), 데이터베이스 상당 부분 복제(저작권법 제93조), 성과물 무단 사용(부정경쟁방지법)이 문제될 수 있음. ‘여기어때’ 크롤링 사건은 형사에서 무죄(대법원 2022. 5. 12. 선고 2021도1533)였으나 민사에서는 부정경쟁행위 손해배상이 인정된 것으로 보도됨. OpenDART 약관(2020.1.21 시행)은 인증키 공유 금지(제19조 제2항)와 이용 허용량(제10조 제4항)을 두고, 상업적 이용·재배포 금지 조항은 없음. 저작권 관련 사항은 저작권법·공공데이터법에 따름(제16조 제4항).
조치
OpenDART 공식 API만 사용하고 허용량 안에서 한 곳씩 순차 수집함. DART 키는 내 PC에만 두고 배포본에는 넣지 않음.
남은 위험
공시 내용의 정확성은 금융감독원도 보장하지 않음(약관 제23조 제1항).

2. 현재 시세 데이터

진행 안 함
쟁점
현재 시가총액·주가로 현재 배수를 보여 줄지가 문제됨. 처음에는 기능에 포함하기로 했던 항목임.
검토
공공데이터포털 ‘금융위원회_주식시세정보’는 공공누리 제4유형(출처표시·상업적 이용금지·변경금지)이고, 데이터 설명에 “상업적 목적 여부와 상관 없이 제3자 무단 제공 및 재배포가 엄격히 금지”, 상업적 이용 시 한국거래소 유료 구매가 필요하다고 적혀 있음. 웹앱에 싣는 것은 제3자 제공이고, VC 업무 사용은 상업적 이용에 가까움.
조치
시세를 저장·표시하지 않고 회사별 외부 시세 링크로 대신함. 지표는 공시 기반(상장 당시 평가, 최근 재무)만 씀.
남은 위험
현재 배수 비교는 회사가 계약한 유료 데이터로 따로 해야 함.

3. 회사 목록(KIND)

조건부
쟁점
신규상장 회사 목록을 어디서 어떻게 가져올지가 문제됨.
검토
KIND는 스크립트 요청에 오류 페이지를 돌려줌(자동 접근 차단). 차단을 우회하면 1번 쟁점의 위험이 커짐. 회사명·종목코드·상장일 같은 사실은 보호 대상이 아님.
조치
우회하지 않고 사람이 화면에서 엑셀을 직접 내려받음. 회사명·종목코드·상장일·상장유형만 쓰고 화면 표기를 그대로 재배포하지 않음.
남은 위험
목록 갱신이 수작업임.

4. 공시 속 개인정보

조건부
쟁점
투자설명서에는 임원 실명·경력과 주주 정보가 있음.
검토
공개된 개인정보도 공개 목적 범위 안에서만 처리할 수 있음(대법원 2016. 8. 17. 선고 2014다235080). 비교기업 검색에는 임원·주주 정보가 필요 없음(최소 처리, 개인정보 보호법 제3조).
조치
임원·주주 장은 받지 않고 사업·공모가 산정 장만 저장함.
남은 위험
사업의 개요 원문에 대표 이름이 섞일 수 있음.

처리: AI에 넣어도 되는가

5. 검색 문장에 딜 정보 혼입(핵심 쟁점)

조건부
쟁점
심사역이 검토 중인 스타트업의 사업 설명을 그대로 넣으면 비밀유지계약 대상 정보가 외부 AI로 나감.
검토
비밀유지의무를 어긴 공개·사용은 계약 위반이자 영업비밀 침해(부정경쟁방지법 제2조 제3호)가 될 수 있음. ‘임베딩만 보내니 안전하다’는 틀림. 임베딩만으로 입력 문장의 상당 부분을 복원할 수 있다는 연구가 있음(Morris 외, EMNLP 2023, 7강). OpenRouter는 요청마다 처리 제공자가 바뀜(7강 실측).
조치
입력 칸에 ‘회사명·비공개 수치·사람 이름 입력 금지’를 고정 표시함. 데이터를 보관·학습하는 제공자를 제외하는 설정(data_collection: deny)을 씀. 검색 문장·질문은 서버 어디에도 저장하지 않고, 기록에는 종류·비용·시간만 남김. 상장사로 찾기는 외부 호출이 없음.
남은 위험
사용자가 안내를 무시하면 막을 수 없음. 실무 사용 전 회사 AI 이용 지침 확인이 필요함.

6. 처리위탁·국외 이전

조건부
쟁점
로그인 이메일과 입력 문장이 Vercel·Supabase·OpenRouter·Gmail을 거침.
검토
개인정보 처리위탁(개인정보 보호법 제26조)과 국외 이전(제28조의8) 검토 대상임. 허용 명단 이메일도 개인정보임(7강).
조치
이메일·인증코드는 해시로만 저장하고, 실행 기록에는 이메일·IP를 넣지 않음. Supabase는 서울 리전. 명단은 서버 환경변수에만 두고 화면에 노출하지 않음.
남은 위험
Vercel·OpenRouter 서버는 해외에 있음. 명단 이용자에게 이 사실을 알려야 함.

7. AI 출력의 정확성

조건부
쟁점
추출값이나 챗봇 답이 틀리면 피어 판단이 흔들림.
검토
RAG도 근거를 붙인 채 틀릴 수 있음. 상용 법률 RAG 도구도 17~33% 환각이 측정됨(Magesh 외 2025, 7강).
조치
정확해야 하는 수치(공모가·배수·재무)는 AI가 아니라 규칙과 정형 API로 추출함. 사업 설명은 AI 요약 대신 공시 원문 첫 문장을 씀. 챗봇 인용은 서버가 실제 목록과 대조해 없는 번호를 지우고, 근거 카드는 우리 데이터로 만들며, 근거가 없으면 정해진 문구로 거절함.
남은 위험
인용 번호가 맞아도 그 문장을 실제로 뒷받침하는지는 사람이 원문으로 확인해야 함.

제공: 보여 줘도 되는가

8. 공시 문서 저작권

조건부
쟁점
공시 원문 일부를 화면에 보여 줘도 되는지가 문제됨.
검토
공시서류는 법령·판결처럼 보호에서 빠지는 저작물(저작권법 제7조)이 아니라 작성 회사의 저작물일 수 있음. 수치·사실은 보호 대상이 아님.
조치
원문은 사업의 개요 앞부분만 짧게 보여 주고 DART 원문 링크를 붙임(제28조 인용, 제37조 출처 표시). 나머지는 수치와 표로만 보여 줌.
남은 위험
발췌 분량의 해석.

9. 투자자문 해당성

진행
쟁점
상장사 배수를 보여 주는 서비스가 투자자문으로 보일 수 있는지가 문제됨.
검토
불특정 다수에게 투자 판단 조언을 영업으로 하면 유사투자자문업 신고 대상임(자본시장법 제101조). 이 앱은 매수·매도 의견과 목표가 없이 공시 수치를 보여 주고, 허용 명단 안에서 무료로 씀.
조치
‘정보 제공용이며 투자 판단이 아님’을 고정 표시함. 챗봇은 투자 권유 질문을 거절함(실측).
남은 위험
공개 서비스로 넓히거나 유료화하면 재검토가 필요함.

10. 기업신용조회업 해당성

진행
쟁점
기업의 재무 정보를 모아 가공해 보여 주는 일이 허가 대상 업무인지가 문제됨.
검토
기업의 거래내용·신용거래능력 등의 정보를 모아 통합·분석·가공해 제공하는 일을 ‘영업으로’ 하면 금융위원회 허가가 필요한 기업신용조회업임(신용정보법 제2조 제8호의3 가목, 제5호). 무료·비영업 학업 도구라 해당하지 않는다고 판단함.
조치
유료화하거나 외부에 제공하지 않음.
남은 위험
시행령이 제외하는 정보의 범위는 따로 확인해야 함.

11. AI 생성 표시

조건부
쟁점
챗봇 답변이 AI가 만든 것임을 알려야 하는지가 문제됨.
검토
인공지능사업자는 생성형 AI 결과물에 생성 사실을 표시해야 함(인공지능 기본법 제31조 제2항, 2026.1.22 시행). 외부 API로 서비스를 만드는 경우도 해당할 수 있음.
조치
답변마다 ‘AI 답변 · 생성형 AI 작성 · 정보 제공용이며 투자 판단 아님 · 근거 공시 확인 필요’를 고정 표시하고, 모델에는 이 고지를 매번 반복하지 않게 함(7강 챗봇 규칙 6과 같은 방식). 사업 설명은 AI 요약이 아닌 공시 원문임을 화면에 밝힘.
남은 위험
표시 방법의 세부 기준은 시행령·가이드라인 확인이 필요함.

사용: 결과를 그대로 써도 되는가

12. 피어 선정 책임

조건부
쟁점
검색 결과를 그대로 피어로 써도 되는지가 문제됨.
검토
유사도는 사업 설명 문장이 비슷하다는 뜻일 뿐, 규모·성장 단계·수익 구조가 같다는 뜻이 아님. 상장 당시 배수는 그때의 시장과 주관사 판단을 반영함. AI 답을 이유로 책임을 벗을 수 없음(Moffatt v. Air Canada, 7강).
조치
화면 아래 ‘읽는 법과 한계’를 고정 표시하고, 피어 확정은 사람이 함.
남은 위험
표의 중앙값을 그대로 가치평가에 쓰는 오용.

13. 실제 업무 사용

진행 안 함
쟁점
만든 도구를 바로 실제 심사 업무에 써도 되는지가 문제됨.
검토
Vercel Hobby 플랜은 개인·비상업 용도만 허용함. 시세 데이터는 상업적 이용이 금지됨. 업무 사용은 회사 AI 이용 지침과 승인이 필요함.
조치
과제·개인 학습용으로만 운영하고 회사명을 표기하지 않음.
남은 위험
개인 도구를 업무에 쓰는 회색지대.

조문과 판례는 과제 검토 목적의 요약이며 법률 자문이 아님.

배수·평가 모형 인용 대조는 수정 전후 모두 불일치 0건. 남은 오류 1건: 매출이 늘었다고 쓴 회사를 ‘감소’ 갈래에 넣음. 인용 번호와 수치는 맞고 분류만 틀린 생성 실패라 자동 검사로 잡히지 않음. ‘전부·몇 곳’ 같은 전체 집계는 상위 8곳만 보는 RAG로는 정확히 답할 수 없어 답변 아래에 “질문과 가까운 8곳(전체 목록 아님)”을 표시함.

실패에서 고친 것

  • 답변 잘림. 출력 한도 1,500에서 답이 잘려 3,000으로 올림. 그래도 모델 내부 추론이 2,731토큰을 써서 답이 빈 경우가 있어 추론을 끔(질문 1회 비용도 약 1.2원 → 0.7원).
  • 느린 추출. 비교기업 정규식이 문서(약 18만 자)마다 12.5초 걸려 ‘○개사를’ 주변만 보도록 바꿈(0.08초).
  • 자동 보안 점검 반영. 오류 메시지에 API 키가 남을 수 있던 문제, 인증코드 시도 횟수를 동시 요청으로 넘길 수 있던 문제(DB 함수로 원자적 증가), 재발송으로 잠금을 피할 수 있던 문제, 솔트 없는 관리자 비밀번호 해시(솔트+scrypt로 교체).

인용 검증은 답변의 번호가 실제 근거 목록에 있는지까지만 확인함. 그 문장을 근거가 실제로 뒷받침하는지는 사람이 원문으로 확인해야 함. 7강에서 다룬, 인용은 있으나 근거가 되지 않는 환각(misgrounded)과 같은 문제임.

한계와 권고

  • 빈 칸. 스팩합병 37곳은 공모가 산정표가 없어 가치 평가 칸이 비어 있음. 2026년 상장 40곳은 첫 사업보고서 전이라 실적이 비어 있음.
  • 대상 범위. 2024년 이전 상장사가 없어 주관사 비교기업 상당수가 목록 밖임(예: 클로봇의 비교기업 4곳 모두).
  • 표적 잠금. 명단 이메일을 아는 사람이 일부러 3번 틀리면 주인이 15분간 로그인할 수 없음. 추측 방어와의 상충으로 받아들임.
  • 업무 적용 전 필요한 것. 회사 AI 이용 지침 확인, 유료 시세 데이터 계약, 상업용 플랜, 명단 이용자에게 국외 처리 고지.
  • 근거 문장 대조. 피어 확정과 배수 해석에 쓰는 수치는 DART 원문 링크로 사람이 확인해야 함.
